VULNÉRABILITÉ 21 octobre 2026

PHP2Shell : deux failles permettant l'exécution de code à distance

Le 21 octobre 2026, le projet PHP a publié des correctifs de sécurité concernant deux vulnérabilités critiques : CVE-2026-109618 et CVE-2026-109619.

Ces failles peuvent permettre à un attaquant distant, dans certaines configurations, d'exécuter du code sur un serveur utilisant une version vulnérable de PHP, sans authentification préalable.

02 / COMPRENDRE

Que s'est-il passé ?

01

La vulnérabilité

Les deux failles concernent la gestion de la mémoire pendant le traitement des requêtes PHP. Une erreur peut laisser des données internes dans un état incorrect et créer une possibilité d'exploitation.

CVE-2026-109618 / CVE-2026-109619
02

Le risque pour le serveur

Une exploitation réussie peut permettre l'exécution de commandes à distance avec les privilèges du processus PHP. Cela peut entraîner une compromission du serveur et exposer les données qu'il héberge.

Exécution de code à distance (RCE)
03

Les systèmes concernés

Plusieurs modes d'exécution de PHP sont concernés, notamment Apache avec mod_php et, selon les configurations, PHP-FPM, php-cgi ou d'autres environnements utilisant PHP.

Serveurs et applications web

06 / MON ANALYSE

Ce que je retiens de cette actualité

Cette actualité montre qu'une vulnérabilité présente dans un composant utilisé par les serveurs web peut devenir un risque important pour toute une infrastructure.

Dans le cadre de mon BTS SIO option SISR, je trouve particulièrement intéressant le rôle de l'administrateur systèmes et réseaux : identifier les équipements concernés, vérifier les versions installées, appliquer les correctifs et surveiller les événements suspects.

Je retiens également qu'une mise à jour ne suffit pas toujours à elle seule : il faut vérifier que les services ont bien redémarré avec la version corrigée et contrôler que le serveur n'a pas déjà été compromis.
